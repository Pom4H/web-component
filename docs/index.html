Component files

A custom-element name maps directly to an HTML file by replacing hyphens with slashes.

<user-card></user-card>      → user/card.html
<studio-mixer></studio-mixer>  → studio/mixer.html

A component file may contain a top-level <script>, markup and <style>. For tiny demos, the same source can live in <template skein="tag-name">.

Reactive state

Inside a component script, this is a deep reactive Proxy. Ordinary property assignments, nested object writes and array mutations are tracked.

<script>
  this.count = 0
  this.user = { name: 'Ada' }
  this.up = () => this.count++
</script>

Synchronous writes naturally settle in one microtask wave. There is no public batch().

Bindings

<h1>Hello {user.name}</h1>
<div title="User {user.name}"></div>
<input .value={user.name}>
<button ?disabled={saving}>Save</button>
<button @click={save}>Save</button>

Expressions in braces are property paths, not arbitrary JavaScript. Use computed() for derivation. Use in={object} for lexical context.

Component composition

Skein uses native Custom Element contracts: properties down, events up.

child / volume-control.html
<script>
  this.value = input('value', .5)
  this.change = event => host.dispatchEvent(
    new CustomEvent('value-change', {
      detail: { value: Number(event.currentTarget.value) },
      bubbles: true,
      composed: true
    })
  )
</script>

<input .value={value} @input={change}>
owner
<volume-control
  .value={volume}
  @value-change={volumeChange}>
</volume-control>

input(name, fallback) declares a reactive host DOM property. If the owner writes that property before the child's HTML file finishes loading, Skein adopts the already-written value when the child mounts. Later element.value = ... writes remain reactive inside the child.

Inputs are one-way. Child-to-owner changes are explicit native CustomEvents; Skein adds no event bus, store or provide/inject protocol. See Skein Studio for a real multi-file composition.

Keyed lists

<article for={projects} key={id}>
  <b>{index}. {title}</b>
  <input placeholder="DOM state survives reorder">
</article>

Existing keys reuse views. Reorder moves node ranges rather than rebuilding them, so browser-local state such as focus and input values can survive.

Conditions

<section if={inspectorOpen}>...</section>

A branch owns a child scope. Hiding it disposes effects, event listeners, nested components and its DOM range.

Computed values and effects

<script>
  this.total = computed(() => this.price * this.quantity)
  effect(() => console.log(this.total))
</script>

computed() is lazy and cached. User effects run after render work settles.

Lifecycle

Disconnect pauses reactive work. Reconnection resumes dirty bindings without rebuilding. Renderer-owned branch/list removals dispose nested Skein elements. Permanent teardown is host.dispose().

window.addEventListener('resize', this.measure, { signal: abortSignal })
const frame = requestAnimationFrame(this.draw)
onCleanup(() => cancelAnimationFrame(frame))

API

Injected component helpers:

input(name, fallback)
computed(fn)
effect(fn)
onCleanup(fn)
host
abortSignal

Public module/global surface stays:

Skein.version
Skein.define(tag, source)

Skein.define() is useful for playgrounds and generated source. Normal multi-file components usually load through the tag-to-path convention.

Production artifact

skein.min.js is currently 14.5 kB raw / 5.3 kB gzip / 4.8 kB Brotli, with zero runtime dependencies.

node tools/build.mjs
node tools/build.mjs --check
node test/run.mjs

The tests execute the generated minified runtime and the real multi-file Studio composition in Chrome/Chromium.
