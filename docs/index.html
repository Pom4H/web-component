Component files

A custom-element name maps directly to an HTML file by replacing hyphens with slashes.

<user-card></user-card>      → user/card.html
<studio-mixer></studio-mixer>  → studio/mixer.html

Skein fetches an unknown tag's source before registering it. A missing file leaves the tag undefined instead of stealing a Custom Element that may belong to another library.

Reactive state

Inside a component script, this is reactive state. Plain objects and arrays are proxied recursively and a shared raw object keeps one Skein Proxy identity across components.

<script>
  this.count = 0
  this.user = { name: 'Ada' }
  this.up = () => this.count++
</script>

Date, Map, Set, DOM/platform objects and class instances stay native and opaque, so internal-slot methods keep valid receivers. Their internal mutations are not reactive automatically.

Bindings

<h1>Hello {user.name}</h1>
<div title="User {user.name}"></div>
<label for={inputId}>Name</label>
<input .value={user.name}>
<button ?disabled={saving}>Save</button>
<button @click={save}>Save</button>

Braces contain strict property paths, not JavaScript expressions. Invalid paths and malformed ./?/@ bindings fail during component compilation. in={...} was removed; outside list item scopes, use full paths.

Component composition

Skein uses native Custom Element contracts: properties down, events up.

child / volume-control.html
<script>
  input('value', .5)
  this.change = event => host.dispatchEvent(
    new CustomEvent('value-change', {
      detail: { value: Number(event.currentTarget.value) },
      bubbles: true,
      composed: true
    })
  )
</script>

<input .value={value} @input={change}>
owner
<volume-control
  .value={volume}
  @value-change={volumeChange}>
</volume-control>

input(name, fallback) installs and seeds a reactive host property. Pre-upgrade property writes are adopted. Later element.value = ... writes remain reactive. Host API collisions such as state, title or dispose throw instead of being shadowed.

Keyed lists

<article each={projects} key={id}>
  <b>{index}. {title}</b>
  <input placeholder="DOM state survives reorder">
</article>

each leaves native HTML for={inputId} available. Explicit keys must be non-null and unique; Skein validates them before reconciliation changes views. Existing keys move real node ranges rather than rebuilding them.

Primitive lists expose the current item as {$value}; list locals also include index and $index.

Conditions

<section if={inspectorOpen}>...</section>

A branch owns a child scope. Hiding it disposes effects/listeners and nested Skein components. Third-party Custom Elements are only disconnected; Skein never calls an arbitrary external dispose().

Computed values and effects

<script>
  this.total = computed(() => this.price * this.quantity)
  effect(() => console.log(this.total))
</script>

computed() is lazy/cached. Synchronous state writes share one microtask, and user effects run after pending render work settles.

Lifecycle

Disconnect pauses reactive work; reconnect resumes dirty bindings without rebuilding. Permanent teardown is host.dispose(). If mount fails during template instantiation, Skein disposes the fresh scope and clears partial shadow DOM before reporting the error.

window.addEventListener('resize', this.measure, { signal: abortSignal })
const frame = requestAnimationFrame(this.draw)
onCleanup(() => cancelAnimationFrame(frame))

Skein.define() defines once. Production hot-reload instance/reload machinery is intentionally absent; Playground recreates its iframe/runtime for edited source.

0.6 migration

- <li for={items} key={id}>...</li>
+ <li each={items} key={id}>...</li>

- <address in={user.address}>{city}</address>
+ <address>{user.address.city}</address>

- this.value = input('value', .5)
+ input('value', .5)

The input assignment form remains compatible. The list/context changes are intentional API simplifications.
