01 / the premise

The browser is already a rendering engine.

DOM

Create once.

Templates compile once per component. There is no virtual tree to recreate and diff on every state change.

SIGNALS

Touch only what changed.

Reactive reads wire state directly to text, attributes, properties, branches and keyed list ranges.

WEB APIs

Keep the good parts native.

CSS animates CSS. SVG stays SVG. Canvas keeps its imperative loop. Skein handles state, ownership and cleanup.

02 / start

One HTML file is enough.

Put an inert component template next to the element, load one module from the CDN, and you are running. No npm. No CLI. No config.

1→1

State write → exact DOM part.

A signal invalidates only the parts that read it. Synchronous writes batch into one microtask. Render effects settle before user effects. Keyed rows move instead of being recreated.

05 / content

Your content doesn't need a renderer. It's already HTML.

Skein does not have SSR today. If search engines, link unfurlers or people without JavaScript need to read something, put it in the document. Let Skein own only the interactive parts.

If the server genuinely needs to compute HTML per request, use a server or static generator for that job and let Skein enhance the result. No fake SSR ceremony is required for a heading that could have been HTML all along.
