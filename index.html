01 / the premise

The browser is already a rendering engine and a component model.

DOM

Create once.

Templates compile once. State writes update exact DOM parts instead of rebuilding a virtual tree.

COMPONENTS

Compose as HTML.

Tag names load HTML files. Owners pass DOM properties down; children dispatch native events up.

WEB APIs

Keep the medium native.

CSS animates, SVG draws, Canvas loops, Web Audio sounds. Skein handles state, identity and lifecycle.

02 / start

One HTML file is enough.

No npm, CLI or config. Prototype inline, then move components into files when the project actually needs boundaries.

DOM properties + CustomEvent.

A child declares this.volume = input('volume', .18). The owner writes the host property through .volume={volume}. Requests travel back as bubbling, composed native events.

04 / rendering

Fine-grained without turning HTML into a programming language.

PATHS

Bindings stay small.

{...} contains property paths. Derived logic belongs in lazy cached computed().

KEYS

Identity survives.

Keyed rows move as real DOM ranges, preserving browser-local input and focus state.

SCOPE

Cleanup has an owner.

Branches and lists dispose effects, listeners and nested components with their DOM.

05 / content

Static content can just be HTML.

Skein has no SSR today. If a heading, article or navigation matters before JavaScript, put it directly in the document and use Skein for the interactive regions.

<main>
  <h1>Native creative web experiences.</h1>
  <p>Already present in the HTML response.</p>

  <interactive-art></interactive-art>
</main>
