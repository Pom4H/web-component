01 / the fit

Keep a static site static. Add real interactive components where they belong.

FILES

Author in HTML.

Each tag can load one ordinary HTML file containing its script, markup and style. No JavaScript component class or generated application bundle.

DOM

Update exact parts.

Deep state mutations update the text, attribute, property or CSS variable that read them while keyed DOM identity survives reorder.

MEDIA

Use the browser directly.

Build instruments and visualizations with real CSS, SVG, Canvas and Web Audio instead of rendering those APIs through a framework abstraction.

02 / one-file start

One HTML file is enough.

Save the page, serve the folder and open it. No npm, compiler, CLI or config. Prototype inline, then move the component into its own HTML file when you want a reusable boundary.

05 / inputs

Static configuration reads like HTML. Live data stays a DOM property.

<ui-metric
  name="Active"
  tone="lime"
  .value={active}>
</ui-metric>

Attribute when static. Property when live.

Primitive literal attributes seed input(). Objects, functions and values that must keep updating use .property={path}. Pre-mount properties always win.

06 / rendering

Fine-grained without turning HTML into a programming language.

PATHS

Bindings stay strict.

{...} contains property paths. --load={reactor.load} updates one CSS custom property without replacing style; derived logic belongs in lazy computed().

EACH

Identity survives.

each={items} key={id} moves real DOM ranges. Native dynamic for={inputId} stays HTML.

SCOPE

Cleanup has an owner.

Branches and lists dispose Skein-owned effects/components without force-disposing external Custom Elements.

07 / coexistence

A missing Skein file does not steal the tag.

Skein fetches component source before customElements.define(). If google/map.html is not there, <google-map> remains free for its real library.

<my-panel></my-panel>
<third-party-chart></third-party-chart>

// my/panel.html exists → Skein defines it
// third/party/chart.html 404 → left untouched

08 / scope

Keep content in HTML. Use Skein for the interactive region.

Skein has no SSR or hydration. Put headings, articles and navigation directly in the document, then add browser-side instruments, visualizations and controls where JavaScript is appropriate. Component scripts execute dynamically, so a strict CSP must permit dynamic evaluation.

<main>
  <h1>Native creative web experiences.</h1>
  <p>Already present in the HTML response.</p>
  <interactive-art></interactive-art>
</main>
