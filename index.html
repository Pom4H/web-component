01 / the premise

The browser is already a rendering engine and a component model.

DOM

Create once.

Templates compile once. State writes update exact DOM parts instead of rebuilding a virtual tree.

COMPONENTS

Compose as HTML.

Tag names load HTML files. Properties carry data, composed events carry actions, native slots carry content.

WEB APIs

Keep the medium native.

Date, Map, Shadow DOM, CSS, SVG, Canvas and Web Audio remain real browser objects instead of framework wrappers.

02 / start

One HTML file is enough.

No npm, CLI or config. Prototype inline, then move components into files when the project actually needs boundaries.

04 / inputs

Static configuration reads like HTML. Live data stays a DOM property.

<ui-metric
  name="Active"
  tone="lime"
  .value={active}>
</ui-metric>

Attribute when static. Property when live.

Primitive literal attributes seed input(). Objects, functions and values that must keep updating use .property={path}. Pre-mount properties always win.

05 / rendering

Fine-grained without turning HTML into a programming language.

PATHS

Bindings stay strict.

{...} contains property paths. Invalid expressions fail early; derived logic belongs in lazy computed().

EACH

Identity survives.

each={items} key={id} moves real DOM ranges. Native dynamic for={inputId} stays HTML.

SCOPE

Cleanup has an owner.

Branches and lists dispose Skein-owned effects/components without force-disposing external Custom Elements.

06 / coexistence

A missing Skein file does not steal the tag.

Skein fetches component source before customElements.define(). If google/map.html is not there, <google-map> remains free for its real library.

<my-panel></my-panel>
<third-party-chart></third-party-chart>

// my/panel.html exists → Skein defines it
// third/party/chart.html 404 → left untouched

07 / content

Static content can just be HTML.

Skein has no SSR today. If a heading, article or navigation matters before JavaScript, put it directly in the document and use Skein for interactive regions.

<main>
  <h1>Native creative web experiences.</h1>
  <p>Already present in the HTML response.</p>
  <interactive-art></interactive-art>
</main>
