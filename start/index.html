ONE FILE.

The shortest path from an empty folder to reactive Web Components. Split and compose components later without changing the medium.

Create index.html.

No package manifest. No scaffold. Any static server or GitHub Pages is enough.

Write the element and its inert template.

index.html
<click-count></click-count>

<template skein="click-count">
  <script>
    this.count = 0
    this.up = () => this.count++
  </script>

  <button @click={up}>
    clicked {count} times
  </button>
</template>

<script type="module"
  src="https://cdn.jsdelivr.net/gh/Pom4H/web-component@main/skein.min.js">
</script>

That is the app.

Skein compiles the template once and connects {count} directly to the state property read by that text binding.

When it grows

Properties. Events. Slots.

Live data flows down through DOM properties. Actions bubble up as composed CustomEvents. Layout/content uses native Shadow DOM slots.

workspace/overview.html
<ui-panel>
  <span slot="heading">Tasks</span>
  <task-board .tasks={tasks}></task-board>
</ui-panel>

<detail-drawer
  .task={selectedTask}
  @move-task={moveTask}>
</detail-drawer>

Inputs

Literal when static. Property when live.

Primitive static configuration reads like HTML. Reactive or non-primitive values use the explicit DOM property form.

<ui-metric
  name="Active"
  tone="lime"
  .value={active}>
</ui-metric>

CSS values

One variable at a time.

--name={path} updates one CSS custom property through style.setProperty(). It does not rebuild the inline style, and variables on a component host inherit into its Shadow DOM.

<reactor-core
  style="display:block"
  --temperature={reactor.temperature}
  --load={reactor.load}>
</reactor-core>

Lists

Use each. Keep HTML for.

Skein does not overload the native for attribute for repetition.

<li each={items} key={id}>
  {index}. {title}
</li>

<label for={inputId}>Name</label>
Prototype inline.
Compose with the browser.
